# romtools-skill

An agent skill that teaches an AI coding agent how to correctly use [RomTools](https://github.com/Danda420/RomTools) — the menu-based Linux CLI for unpacking/repacking Android partitions — instead of letting it guess.

## What it is

`skills/romtools/SKILL.md` is a single, self-contained skill file covering the whole RomTools workdir:

- Repacking an unpacked partition into `output/` — erofs, ext4 and f2fs writers, with the correct function for each.
- EROFS work: unpack, autogenerated `fs_config` / `file_contexts`, validating **only newly added** contexts against sepolicy, and `mkfs.erofs` options.
- Android boot images: `bbootimg` unpack/pack, signed-by-default output.
- Strict hygiene: unpacked files only under `ROM_WORKDIR/<project>/`, packed output only in `<RomTools root>/output/`, no stray files, scratch cleanup, and no noisy `git status` checks.
- Safe behavior: list `ROM_WORKDIR/` and ask when a project name is vague; ask when a custom script match is ambiguous; never hand-write configs; never invent script inputs.

It was written against an install rooted at `/mnt/project/RomTools`. The bootstrap prompt below makes the agent re-point every path to your actual RomTools directory.

## Install / bootstrap prompt

Copy the entire block below and paste it to **any agent** (OpenCode, Claude Code, Cursor, etc.). It will clone this repo, locate or install RomTools, patch the skill's paths, and adopt the output-reporting format.

```text
Set up the romtools skill for me.

1. Clone this repository: https://github.com/ryanistr/romtools-skill.git
   Put the clone in a scratch location (use your TMPDIR, e.g. /tmp/opencode/romtools-skill;
   never drop it directly in $HOME). Read README.md and skills/romtools/SKILL.md.

2. Ask me where my RomTools directory is installed. DO NOT GUESS IT.
   - If I give you a path, verify it looks like RomTools: it must contain
     tool/functions, tool/bin/, input/, output/ and ROM_WORKDIR/. If it does not,
     tell me and ask again.
   - If I don't have RomTools installed, ask me WHERE TO SAVE it first, then clone
     https://github.com/Danda420/RomTools.git into that location. Wait for my answer
     before cloning. There are two similarly named upstream repos; use exactly
     Danda420/RomTools (the "CLI ROM Tools for Linux" one), not RomTools-Android.

3. Install the skill: copy skills/romtools/SKILL.md into this agent's skills directory.
   Detect the correct directory; if unsure, ask me. For OpenCode it is
   ~/.agents/skills/romtools/SKILL.md. If a romtools skill already exists there,
   show me the diff before overwriting it.

4. Update the installed SKILL.md so every hardcoded /mnt/project/RomTools path points
   to the confirmed RomTools root from step 2, including the example in the
   "Reporting the result" section. Confirm the final paths with me.

5. From now on, use this skill for any RomTools work. Follow its rules: list ROM_WORKDIR
   and ask when a project name is vague or ambiguous; honor an explicit target
   filesystem (ext4/f2fs/erofs) instead of defaulting to erofs; list tool/custom_scripts/
   before using a script and ask when the match is ambiguous; run the embedded autogen
   tools first and validate only newly added contexts; keep all output in <root>/output/;
   clean up scratch files; and never use git status as a repack-output check.

6. Whenever a RomTools execution finishes, end your response with the full absolute
   output path in exactly this form (using the real path and the actual filename):

   Repack done...
   Output : <confirmed RomTools root>/output/system.erofs.img

   Use the real produced filename, e.g. <name>.signed.img for signed boot images.

7. Confirm setup is complete and tell me the installed skill path and the RomTools root
   you configured.
```

## Updating

```bash
git -C <your clone> pull
cp <your clone>/skills/romtools/SKILL.md <agent skills dir>/romtools/SKILL.md
```

Then re-apply step 4 of the prompt if your RomTools root changed.
