# romtools-skill

An agent skill that teaches an AI coding agent how to correctly use [RomTools](https://github.com/Danda420/RomTools) — the menu-based Linux CLI for unpacking/repacking Android partitions — instead of letting it guess.

## What it is

`skills/romtools/SKILL.md` is a single, self-contained skill file covering the whole RomTools workdir:

- Repacking an unpacked partition into `output/` — erofs, ext4 and f2fs writers, with the correct function for each.
- EROFS work: unpack, autogenerated `fs_config` / `file_contexts`, validating **only newly added** contexts against sepolicy, and `mkfs.erofs` options.
- Android boot images: `bbootimg` unpack/pack, signed-by-default output.
- Strict hygiene: unpacked files only under `ROM_WORKDIR/<project>/`, packed output only in `<RomTools root>/output/`, no stray files, scratch cleanup, and no noisy `git status` checks.
- Safe behavior: list `ROM_WORKDIR/` and ask when a project name is vague; ask when a custom script match is ambiguous; never hand-write configs; never invent script inputs.

It was written against an install rooted at `/mnt/project/RomTools`. The bootstrap prompt below makes the agent re-point every path to your actual RomTools directory.

## Repo layout

```
README.md
skills/romtools/SKILL.md   <- the agent skill
mcp/server.js              <- optional local MCP server (discovery/config only)
```

## MCP companion (recommended)

`mcp/server.js` is a dependency-free local MCP server — plain Node.js, no `npm install`. It replaces long shell pipelines with short structured calls:

- workdir/config: `get_config`, `set_workdir`, `set_project`, `create_project`, `get_env`, `set_env`
- discovery: `list_projects`, `find_project`, `list_partitions` (includes config/context line counts), `list_output`, `list_binaries`, `list_boot_images`
- scripts: `list_scripts`, `find_script`
- execution: `repack_partition` (erofs/ext4/f2fs), `unpack_image`, `repack_boot_image`, `unpack_boot_image`

**Execution guard:** repack/unpack tools refuse to run until `set_workdir` and `set_project` have been called. `get_config` reports `ready_for_execution` and a mismatched `project` argument is rejected — the agent must run discovery and select the project first.

It **never repacks** — the skill keeps all the policy rules (ask on ambiguity, explicit filesystem, autogen-first, signed boot images, output discipline). The chosen RomTools root is stored in `mcp/config.json` (gitignored), or set `ROMTOOLS_ROOT` in the environment.

OpenCode registration:

```sh
opencode mcp add romtools --global -- node /absolute/path/to/romtools-skill/mcp/server.js
opencode mcp list   # ✓ romtools connected
```

Other agents: register `node /absolute/path/to/romtools-skill/mcp/server.js` as a local stdio MCP server named `romtools`. Then call `set_workdir` once with your RomTools root.

## Install / bootstrap prompt

Copy the entire block below and paste it to **any agent** (OpenCode, Claude Code, Cursor, etc.). It will clone this repo, locate or install RomTools, patch the skill's paths, and adopt the output-reporting format.

```text
Set up the romtools skill for me.

1. Clone this repository: https://github.com/ryanistr/romtools-skill.git
   Put the clone in your platform's scratch/temp directory (for example
   "$TMPDIR/romtools-skill"); never drop it directly in $HOME. Read README.md
   and skills/romtools/SKILL.md.

2. Ask me where my RomTools directory is installed. DO NOT GUESS IT.
   - If I give you a path, verify it looks like RomTools: it must contain
     tool/functions, tool/bin/, input/, output/ and ROM_WORKDIR/. If it does not,
     tell me and ask again.
   - If I don't have RomTools installed, ask me WHERE TO SAVE it first, then clone
     https://github.com/Danda420/RomTools.git into that location. Wait for my answer
     before cloning. There are two similarly named upstream repos; use exactly
     Danda420/RomTools (the "CLI ROM Tools for Linux" one), not RomTools-Android.

3. Install the skill: copy skills/romtools/SKILL.md into this agent's skills directory.
   Detect the correct directory; if unsure, ask me. For OpenCode it is
   ~/.agents/skills/romtools/SKILL.md. If a romtools skill already exists there,
   show me the diff before overwriting it.

4. Update the installed SKILL.md so every hardcoded /mnt/project/RomTools path points
   to the confirmed RomTools root from step 2, including the example in the
   "Reporting the result" section. Confirm the final paths with me.

5. Ask me whether this agent supports MCP servers.
   - If it does not, ask me whether I want MCP support installed/configured. If I say
     no, skip every MCP step and use only the skill's manual shell fallbacks. If I say
     yes, help me enable MCP for this agent before continuing (do not guess the mechanism).
   - If it does support MCP, ask me whether I want to use the romtools MCP. If I say no,
     skip MCP setup entirely.
   - Never register or use the MCP without my explicit answer.

6. If I chose to use the romtools MCP, install or UPDATE it from this repo: copy
   `<clone>/mcp/server.js` to the server path this agent runs, or register the command
   directly from the clone (OpenCode:
   `opencode mcp add romtools --global -- node <clone>/mcp/server.js`). If a "romtools"
   MCP is already registered, re-point it to the updated server.js — never leave a stale
   copy running. Verify it connects, then call romtools_set_workdir with the confirmed
   RomTools root and romtools_get_config to verify, then romtools_find_project
   followed by romtools_set_project — repack/unpack tools refuse to run until
   a project is selected. Use romtools_find_project, romtools_list_projects,
   romtools_repack_partition, romtools_unpack_image,
   romtools_list_boot_images, romtools_unpack_boot_image, romtools_repack_boot_image
   and romtools_list_scripts instead of long hand-typed pipelines. If I ask for a
   project that does not exist, show me the available list and ask whether to pick
   one or create a new project; only create with my explicit confirmation
   (romtools_create_project with confirm:true), never silently. Boot repacks are
   signed by default; unsigned only if I explicitly ask for it.

7. From now on, use this skill for any RomTools work. When the romtools MCP is available
   you MUST use it for discovery, config, repack and unpack; manual shell is a fallback
   only when the MCP is unavailable or I declined it. Follow its rules: ask when a
   project name is vague or ambiguous; honor an explicit target filesystem
   (ext4/f2fs/erofs) instead of defaulting to erofs; check available custom scripts before
   using one and ask when the match is ambiguous; run the embedded autogen tools first and
   validate only newly added contexts; keep all output in <root>/output/; clean up scratch
   files; and never use git status as a repack-output check.

8. Whenever a RomTools execution finishes, end your response with the full absolute
   output path in exactly this form (using the real path and the actual filename):

   Repack done...
   Output : <confirmed RomTools root>/output/system.erofs.img

   Use the real produced filename, e.g. <name>.signed.img for signed boot images.

9. Confirm setup is complete and tell me the installed skill path, the RomTools root,
   and whether the romtools MCP is connected (or that I declined it).
```

## Updating

```bash
git -C <your clone> pull
cp <your clone>/skills/romtools/SKILL.md <agent skills dir>/romtools/SKILL.md
# if you use the MCP, also refresh/re-register the server:
cp <your clone>/mcp/server.js <path the MCP server runs>
```

Then re-apply step 4 of the prompt if your RomTools root changed, and step 6 if the MCP registration needs updating.
